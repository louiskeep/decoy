## 1. FRAME

### Problem

A first-time user on a 2-table, 5-column dataset hit 14 defects. Three of them are classes, not one-offs:

1. **An exception escapes a command as a Rich traceback.** The root app is a plain `typer.Typer`
   (`src/decoy/__main__.py:70-75`) with Typer's pretty tracebacks on, and the console script points at it
   directly (`pyproject.toml:200`). Any exception a command does not catch prints internal paths and locals.
2. **Internal names reach user text.** Hidden default subcommands appear in usage lines (`decoy scan _scan`,
   `decoy validate _gate`), and ticket ids, a private engine module path and a platform repo path sit in
   help, templates and `explain` bodies.
3. **`--json` envelopes name the wrong command.** `validate compile --json` reports `"compile explain"`
   (`compile_explain.py:254,304,339`) and `validate preflight --json` reports `"preflight"`
   (`preflight.py:795`), names left over from before the commands were re-parented.

The rest are single defects with one root cause each (section 4).

### Guarantee (what V1 promises)

1. No command prints a Python traceback without `--verbose` (or `DECOY_DEBUG=1`). An uncaught exception
   prints one line and exits with the same code it exits with today (1). Usage errors still exit 2,
   Ctrl-C 130, and an explicit `SystemExit(n)` n.
2. No user-facing string (help, epilog, usage, `explain` bodies, error and hint text built from string
   constants, shipped templates) contains an internal ticket id, a hidden command name, a private engine
   module path or a platform repo path.
3. Every `--json` envelope's `command` value is a real command path, optionally followed by a known
   argument value.
4. Each item in section 4 behaves as its "After" column says, and exit codes for every existing error class
   are unchanged.

### Non-goals (V1)

- Changing which exit code an error class maps to (row 24e limit).
- Rewording STORM (row 56); wizard prompts (row 32b).
- Redesigning `run` output beyond adding rows, files and tables.
- Engine-side fidelity scoring (why the QA run scored 0.000); only the label is fixed here (F2).

## 2. Established solutions

- **Click/Typer error model**: `ClickException`, `Abort` and `Exit` carry their own exit codes, and Click's
  `_main` already maps `KeyboardInterrupt` to 130 and `EOFError` and EPIPE to a quiet exit 1; anything else
  is a crash. Typer documents `pretty_exceptions_enable=False` to stop local-variable dumps. We keep that
  model and add one guard for the "anything else" case.
- **git, cargo, gh**: an internal error prints one line ("fatal:", "error: internal error") and asks for a
  verbose rerun. Tracebacks are opt-in (`RUST_BACKTRACE`, `GIT_TRACE`). We use `--verbose` and the already
  documented `DECOY_DEBUG=1`.
- **Python logging for libraries** (the stdlib HOWTO, "Configuring Logging for a Library"): a library adds a
  `NullHandler` to its top logger and never writes files unless asked. E-a follows it.
- **Copy linting** (Vale, write-good, Microsoft style rules): banned-term lists applied to every user
  string, with an allowlist for justified hits. AT-S2 is that pattern over the Click tree, `explain`, string
  constants and templates.
- **JSON CLI envelopes** (gh `--json`, kubectl `-o json`): the command identity in output matches the
  invoked path. AT-S3 checks it from the command tree, not a hand list.

## 3. Design notes

### Choke points and registries

| Class | Choke point | Registry | Sentry |
|---|---|---|---|
| Traceback escape | `_GuardedGroup.invoke` on the root app in `src/decoy/__main__.py` (below) | `_PASS_THROUGH` tuple in `__main__.py`: `typer.Exit`, `typer.Abort`, `_CLICK_EXCEPTION`, `EOFError` | AT-S1 `tests/sentry/cli_text/test_no_traceback_escape.py` |
| Internal names | `_default_group.py` (usage path) plus the text itself | `BANNED_USER_TEXT` patterns with an allowlist in the sentry file | AT-S2 `tests/sentry/cli_text/test_user_text_internal_names.py` |
| JSON command names | none (literals at each `emit_json` site) | derived from the Typer tree at test time; `KNOWN_ARGUMENT_VALUES` and a variable allowlist in the sentry | AT-S3 `tests/sentry/cli_text/test_json_command_names.py` |

**The guard.** `_GuardedGroup(TyperGroup)` overrides `invoke(ctx)`:

- Before `super().invoke(ctx)`, it reads `verbose = "--verbose" in args or "-v" in args` over
  `[*ctx._protected_args, *ctx.args]` (CliRunner does not set `sys.argv`, so argv cannot be used) and
  `debug = os.environ.get("DECOY_DEBUG") == "1"`.
- `except _PASS_THROUGH: raise`, then `except OSError as exc` re-raises when `exc.errno == errno.EPIPE`,
  then `except Exception as exc` (never `BaseException`, so `KeyboardInterrupt` and `SystemExit` pass to
  Click's `_main` untouched). On `debug` it re-raises. Otherwise it builds the stderr console with
  `setup_output(json_=False, quiet=False, verbose=verbose)` and prints
  `error: internal error (<ClassName>)` with `hint: rerun with --verbose for the full traceback.`; under
  `verbose` it prints the row-data note and `print_traceback(state)` (the `scan.py:798-802` pattern). It
  raises `typer.Exit(1)`.
- `_CLICK_EXCEPTION = typer._click.exceptions.ClickException` is the one import from a private module
  (recurring-defect class 6). It is a single constant, Typer is already pinned `>=0.26.7,<0.27` (`pyproject.toml:120`), and
  AT-S1 asserts `issubclass(typer.BadParameter, _CLICK_EXCEPTION)` so an upgrade that moves it fails loudly.
- The root app is built as `typer.Typer(cls=_GuardedGroup, pretty_exceptions_enable=False, ...)`.

The guard lives in `__main__.py` (163 lines now, about 215 after) because `cli/` is flat at 34 entries and
the guard belongs to the root app.

### Engine changes (data and logging behavior belong in the engine)

- **E-a, log file default.** `internal/logging.py:111` defaults `file` to `"logs/decoy_engine.log"`, and the
  CLI's ambient file policy (`:113-120`) lets it open under the user's cwd on the first lazy logger
  (`internal/base.py:26,72`). Change the default to no file: a log file is written only when config names
  one. When neither a file nor a console handler is configured, attach `logging.NullHandler()` to the
  `decoy_engine` logger, so Python's last-resort handler does not start printing engine warnings (the
  capacity advisory at `_capacity_eval.py:517`, reroute, spill, formula and distribution warnings) to
  stderr. Platform and server runs already ignore the file setting (non-ambient policy). This also retires
  the CLI's chdir workaround in `ci/engine_logging.py:29-33` (left in place; follow-up F3).
- **E-b, public relationship builder.** Item 2 needs the config's `relationships:` as profile-layer
  `Relationship` tuples without a real profile. The engine already has the converter as a private helper
  (`profile/_source.py:301` `_build_relationships(relationships_config: list[dict[str, Any]])`, used at
  `:128`). Export it as `decoy_engine.profile.relationships_from_config(relationships_config)` with the same
  argument (rename plus export; the private name goes, pre-GA hard delete). One builder, no CLI copy.
- **Release.** The CLI pins `decoy-engine==0.19.0` from a git tag, and 10 engine commits since v0.19.0
  ride along with any bump. E1 therefore needs an engine release (step R in section 12), which is
  claudeorchestrator's call; C1 waits on it, and nothing else does.

### 4.8 Item 8: `report fidelity` prints "PASS grade F"

- Root cause: `--mode` defaults to `report` (`report.py:1661`). `--min-grade` and `--min-score` only add
  thresholds (`:1795-1800`), and the engine's `_verdict_for` returns `"pass"` in report mode even when

  thresholds)`; with thresholds (from `--min-grade`, `--min-score` or a `--policy` file with `mode:

  engine report's violations (0 allowed). Neutral style for both. Warn and fail modes are unchanged; the
  JSON `verdict` stays `"pass"` (engine contract); no exit code moves.
- Test: AT-8 default mode human line has no "PASS"; `--min-grade B` in default mode on a grade F run prints
  the not-enforced line and exits 0 (unchanged); `--mode fail --min-grade B` prints FAIL and exits 4 as
