## 1. FRAME

### Problem

A first-time user on a 2-table, 5-column dataset hit 14 defects. Three of them are classes, not one-offs:

1. **An exception escapes a command as a Rich traceback.** The root app is a plain `typer.Typer`
   (`src/decoy/__main__.py:70-75`) with Typer's pretty tracebacks on, and the console script points at it
   directly (`pyproject.toml:200`). Any exception a command does not catch prints internal paths and locals.
2. **Internal names reach user text.** Hidden default subcommands appear in usage lines (`decoy scan _scan`,
   `decoy validate _gate`), and ticket ids and a platform repo path sit in help and `explain` bodies.
3. **`--json` envelopes name the wrong command.** `validate compile --json` reports `"compile explain"`
   (`compile_explain.py:254,304,339`), a name left over from a retired command.

The rest are single defects with one root cause each (section 4).

### Guarantee (what V1 promises)

1. No command prints a Python traceback without `--verbose`. An uncaught exception prints one line and exits
   with the same code it exits with today (1).
2. No user-facing string (help, epilog, usage, `explain` bodies, error and hint text) contains an internal
   ticket id, a hidden command name or a platform repo path.
3. Every `--json` envelope's `command` value is a real command path.
4. Each item in section 4 behaves as its "After" column says, and exit codes for every existing error class
   are unchanged.

### Non-goals (V1)

- Changing which exit code an error class maps to (row 24e limit).
- Rewording STORM (row 56); wizard prompts (row 32b).
- Redesigning `run` output beyond adding rows, files and tables.
- Engine-side fidelity scoring (why the QA run scored 0.000); only the label is fixed here (F2).

### Failure modes

| # | Failure | Guard |
|---|---|---|
| F-1 | A new command path raises an unhandled engine error and prints a traceback | root crash guard plus AT-S1 |
| F-2 | A new help string or `explain` topic cites a ticket | AT-S2 registry sentry |
| F-3 | A new `--json` envelope copies a stale command name | AT-S3 |
| F-4 | The crash guard swallows `typer.Exit` or `Abort` and changes an exit code | guard catches only non-Click exceptions; AT-S1 checks Exit and Abort pass through |
| F-5 | The crash guard prints `str(exc)`, which can carry cell data | it prints the class name only, as `scan.py:780-786` does |
| F-6 | Item 2's fix makes `validate compile` reject configs it used to accept | OQ1; the rejection is the bug fix |

## 2. Established solutions

- **Click/Typer error model**: `ClickException`, `Abort` and `Exit` carry their own exit codes; anything else
  is a crash. Typer documents `pretty_exceptions_enable=False` to stop local-variable dumps. We keep Click's
  model and add one guard for the "anything else" case.
- **git, cargo, gh**: an internal error prints one line ("fatal:", "error: internal error") and asks for a
  verbose rerun. Tracebacks are opt-in (`RUST_BACKTRACE`, `GIT_TRACE`). We use `--verbose`.
- **Copy linting** (Vale, write-good, Microsoft style rules): banned-term lists applied to every user
  string, with an allowlist for justified hits. AT-S2 is that pattern over the Click tree and `explain`.
- **JSON CLI envelopes** (gh `--json`, kubectl `-o json`): the command identity in output matches the
  invoked path. AT-S3 checks it from the command tree, not a hand list.

### Choke points and registries

| Class | Choke point | Registry | Sentry |
|---|---|---|---|
| Traceback escape | `_GuardedGroup.invoke` on the root app in `src/decoy/__main__.py` (catches every exception that is not `click.exceptions.Exit`, `Abort` or `ClickException`; prints `error: internal error (<ClassName>); rerun with --verbose`; exits 1; `--verbose` in argv re-raises) | none needed: one site | AT-S1 `tests/sentry/test_no_traceback_escape.py` |

The crash guard lives in `__main__.py` (163 lines now) because `cli/` is flat at 34 entries and the guard
belongs to the root app. It reuses the existing message shape of `scan.py:780-786` (class name only) and
does not import `print_traceback`; `--verbose` re-raises so Python prints the trace.

### Engine changes (data and logging behavior belong in the engine)

- **E-a, log file default.** `internal/logging.py:111` defaults `file` to `"logs/decoy_engine.log"`, and the
  CLI's ambient file policy (`:113-120`) lets it open under the user's cwd on the first lazy logger
  (`internal/base.py:26,72`). Change the default to no file: a log file is written only when config names
  one. Platform and server runs already ignore the setting (non-ambient policy), so only CLI behavior moves.
  This also retires the CLI's chdir workaround in `ci/engine_logging.py:29-33` (left in place; follow-up F3).
- **E-b, public relationship builder.** Item 2 needs the config's `relationships:` as profile-layer
  `Relationship` tuples without a real profile. The engine already has the converter as a private helper
  (`profile/_source.py:301` `_build_relationships`, used at `:128`). Export it as
  `decoy_engine.profile.relationships_from_config(config_dict)` (rename plus export; the private name goes,
  pre-GA hard delete). One builder, no CLI copy.

### 4.1 Item 1: validate and preflight traceback on an unresolvable relationship namespace

- Repro: a pipeline with `relationships: [{parent: patients.patient_id, child: visits.patient_id}]` and no
  namespace on either column. `decoy validate pipeline.yaml` and `decoy validate preflight pipeline.yaml`.
- Root cause: `_check_capacity` (`cli/preflight.py:458-485`) calls `estimate_job_capacity`, which compiles the
  plan; the engine raises `NamespaceConfigError` (a `PlanCompileError`, `relationships/_namespace.py:142`).
  The handler catches only `ExecutionError` and re-raises the rest. Reached from `preflight.py:760` and the
  gate's `gate/_layers.py:288`.
- Fix: catch `PlanCompileError` (public, `decoy_engine.plan`, already imported by `compile_explain.py:320`)
  in `_check_capacity` and record a FAIL with the error's `code` and `path`, plus a hint naming
  `decoy explain pipeline` for namespaces. The crash guard covers any other escape.
- Test: AT-1 both commands print a `namespace_missing` FAIL row, no "Traceback", exit code equals the code
  `validate` returns for any other compile FAIL today.

### 4.2 Item 2: `validate compile` says "no FK dependencies detected" with one declared

- Repro: same file, `decoy validate compile pipeline.yaml`.
- Root cause: no-profile mode (the default) builds the sentinel profile with `relationships=()`
  (`cli/plan.py:48-71`, `compile_explain.py:225`), so the engine's graph build (`plan/_compile.py:283-287`)
  sees no relationships, `plan.ordering` is empty, and `compile_explain.py:422-425` prints the message.
- Fix: `empty_profile_for_no_profile` fills `relationships` from `relationships_from_config(config_dict)`
  (E-b). The compile then raises the same `namespace_missing` error `validate` reports (rendered by the
  existing `_compile_error`, `compile_explain.py:236-238`), and a resolvable relationship produces an
  ordering table. The fallback message only prints when no relationship is declared.
- Test: AT-2 (unresolvable: error naming the relationship, exit 1 as every compile error today; resolvable:
  ordering lists `patients` before `visits`).

### 4.3 Item 3: internal names in user text

### 4.7 Item 7: false "output directory does not exist" warning

- Repro: target `path: out/patients.csv` with no `out/`; `decoy validate`.
- Root cause: `_check_target_overwrite` (`preflight.py:282-305`) resolves the path against the process cwd

- Fix: resolve with the same `resolve_path` and the config directory (pass `config.parent` from
  `preflight.py:757`); drop the `parent_missing` warning; warn only when the nearest existing ancestor is not
  a directory or is not writable (`target.<t>.parent_unwritable`).
- Test: AT-7 missing `out/` gives no warning; a file named `out` gives the unwritable warning; an existing
  target relative to the config dir (run from another cwd) gives `would_overwrite`.

- Fix: in human output, report mode prints `REPORT ONLY (no thresholds)` in neutral style instead of PASS;

- Test: AT-8 default mode human line has no "PASS"; `--min-grade B` on a grade F run still prints FAIL with

### 4.14 Item 14: `run` summary lacks rows, files and tables
