## Round 3 fixes (round-2 reviews of `6123a75`)

- `ci-template-lint` no longer builds anything. `actionlint-py` is sdist-only, so pip built it with
  floating build dependencies. The lock now holds only `check-jsonschema` and its wheels, compiled
  with `--no-build` by `scripts/dev/lock.sh` (which also checks it) and installed with
  `--require-hashes --only-binary :all:`. actionlint comes from its release binary through
  `scripts/dev/fetch_ci_binary.py`; the url and sha256 are `[[binary_tool]]` in
  `ci/install-policy.toml`. The scanner refuses `--no-binary`, a missing `--only-binary :all:`,
  and `curl` or `wget` in a workflow.
- The shared core gained `uv_subcommand`, `tool_fetch`, global pip options before the subcommand,
  `-f` and `--find-links` as index overrides, and the `PIP_*` / `UV_*` index variables (command
  prefix, step, job and workflow `env`). The CLI flags `uv sync|add|remove|lock|pip sync` after
  global options and every uvx, `uv tool` and pipx fetch.
- Validators use `fullmatch`; the CLI wheel must be a local `dist/` path.
- The core is now vendored in both directions. The engine branch `fix/ci-x-shared-shell-core`
  holds the same bytes; each ledger records the other repository's commit, and a test fetches that
  file and compares. Editing one copy and recomputing its ledger hash still fails.
