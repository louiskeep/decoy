## What 5-v1 adds

One characterization test, `tests/sentry/test_mask_secret_ref_shape.py::test_vault_ref_is_refused_without_echo`,
over `run`, `tokenize`, `unmask`, `report vault` and `decoy.mask()`. Each case first writes real
inputs (source, masked file, vault) under a valid `env:` secret, so the only fault left is a
well-formed `vault://` reference whose path carries a canary. Every surface refuses with
`secret_provider_unknown` and the constant CLI text (`_mask_secret_guidance.SECRET_REMEDIES`),
in console, `--json` and `--verbose` modes. Verbose `run` also emits its documented diagnostic
traceback after that exact refusal. `decoy.mask()` instead raises the engine's exact constant
`SecretProviderUnknown` message. No parsed path segment or query pair from the reference appears
in stdout, stderr or exception text, and no file under the test's directory is created or changed
(the tree is compared byte for byte before and after). It asserts nothing about source-read order.
No logic changed.

It was green on first run, as the plan expected (CHAR, not red-first). The acceptance mutation
shows it is not vacuous. Assertion-specific mutations that have not run are marked for the gate:
