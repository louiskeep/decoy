## Deviations

1. **C-T2 `chunked` cannot pass as written.** The plan (4.4, 5.2) expects phase spans on the
   `--chunked` path; the engine emits none there. Needs an engine change (phase events from
   `run_mask_pipeline_chunked`) or an owner call to relax the cell. The builder left the
   cell red, not weakened.
   Ruling 2026-11-12: the phase assertions stay as written for `chunked`, marked strict
   xfail, so the cell fails the day the engine emits phase events there and the mark has to
   go. A new cell, `test_chunked_run_exports_one_ended_root_span`, pins what a chunked run
   does export today. The limit is in the guide. The engine change is V2-LOG: a root span
   without phases breaks no run, loses no data and leaks nothing.
2. One `use_progress` on the run's `ExitStack` instead of `progress=` on the call: it covers
   full-frame, chunked and preview with no edit to `_execute.py`, which keeps the merge with
   PROJECT-LAYOUT P4 small.
3. Flush happens in `_flow`'s `finally`, so on the `EXIT_FINDINGS` arms after it (post-validate
   enforce) the spans are exported before that exit code is decided. Exit code unaffected.
4. C-T7 checks the stack refusal only on the certified platform (Linux x86-64) and skips on
   macOS, where the engine refuses earlier with `dp_platform_uncertified`. The guide assertions
   run everywhere.
5. C-T3 puts the DSN-shaped marker in `--key-label` (argv) and the marker path in the config
   and `--evidence-out`; no run option takes a real DSN.
6. `docs/cli-reference.md` unchanged: its `--otel-endpoint` text stays true.
7. mypy: not installed in the VM venv; the local engine venv mypy lacks the CLI's dependencies,
   so it was not a usable check.
