# ADR-0001 — BUSL-1.1 with 4-year auto-Apache conversion for the CLI

> **Status:** Accepted
> **Date:** 2026-05-06

## Context

The CLI (`decoy`) is the only repo intended for public release. The engine (`decoy-engine`) is a shared Python library used by both the CLI and the private platform; the platform itself (`decoy-platform`) is closed-source and licensed commercially.

The CLI sits in front of buyers' decision-making. Compliance and procurement teams want source visibility before they install something that touches sensitive data; security teams want to audit it. Pure proprietary licensing kills that conversation before it starts.

At the same time, fully permissive licensing (Apache 2.0 / MIT) lets a competitor — a managed-services vendor or a cloud provider — take the CLI, host it as a service, and compete with the platform without contributing back. That dynamic has played out repeatedly in infrastructure / data tools and is the canonical reason for the BUSL class of licenses.

The team's positioning depends on the platform being the commercial moat. The CLI is a customer touchpoint and a credibility signal; it should be source-available now, fully permissive eventually, and never host-and-resell-able by a competitor in the meantime.

## Decision

License the CLI under **Business Source License 1.1 (BUSL-1.1)** with a **4-year auto-conversion to Apache 2.0**.

Concretely:

- Each release tag carries a `Change Date` exactly 4 years in the future. On that date, the release auto-converts to Apache 2.0.
- Use restriction: the CLI may not be offered as a hosted service to third parties without a separate commercial agreement. All other uses (internal use, modification, redistribution) are permitted.
- Additional grant: explicit allowance for buyers using the CLI inside their own infrastructure as part of their normal data operations.

`LICENSE` file at the repo root carries the full BUSL-1.1 text plus the Change Date and Additional Use Grant clauses. `pyproject.toml` sets `license = "BUSL-1.1"`.

## Consequences

**Negative:**
- Some procurement teams flag BUSL as "not open source" by OSI's strict definition (it isn't, until the Change Date). Expect to write a one-page explainer for these conversations. Some buyers will refuse on principle; we accept those losses.
- Cannot accept upstream contributions without a Contributor License Agreement (CLA), since the BUSL-1.1 grant requires the licensor to retain copyright control through the Change Date. CLA workflow needs to be set up before opening the repo to PRs.
- Deprecation of older releases is governed by their individual Change Dates, not by current decisions. Once a release ships under BUSL-1.1, we can't retroactively make it more restrictive.
- Some CI / dependency-scanner tools flag BUSL-1.1 as a "non-permissive license" warning. Mostly informational; will need a known-warnings list in the deployment guide.

**Positive:**
- Compliance / procurement / security teams can read the source. The conversation moves from "we can't tell what it does" to "we read it, here are our questions" — which is the conversation we want.
- Competitors cannot host-and-resell. The 4-year window is long enough to establish the platform's market position; after that the code is Apache 2.0 and the moat is execution speed and the commercial platform itself.
- The auto-conversion clause is a credible signal of intent — contributors and adopters know the code becomes fully open source on a fixed timeline, which removes the "what if they pull the rug?" concern that pure source-available licensing creates.
- Pattern is well-tested in the data / infrastructure space (Sentry, CockroachDB, MariaDB, HashiCorp's stack post-2023). Buyers who've seen it before don't need re-education.

## Alternatives considered

- **Pure Apache 2.0 / MIT.** Rejected: lets a competitor monetize the CLI as a hosted service. The whole point of having a commercial platform is undermined if the CLI is hostable.
- **Pure proprietary.** Rejected: the buyer's compliance / security / procurement team can't audit closed-source software that touches sensitive data without significant friction. Source visibility is a sales requirement, not a nice-to-have.
- **AGPL.** Rejected: AGPL's "network use" clause is contagious for buyers who modify the CLI for internal use behind their firewall. Most enterprise buyers' legal teams refuse AGPL-licensed software outright — same outcome as proprietary, with extra confusion.
- **Elastic License / SSPL.** Rejected: similar shape to BUSL but without the auto-conversion clause. The auto-conversion is what makes BUSL credible to contributors and to the open-source ecosystem. SSPL also has additional viral clauses that BUSL doesn't, which makes it harder for buyers to comply with.
- **Source-available with no use restriction.** Rejected: doesn't solve the host-and-resell problem.
