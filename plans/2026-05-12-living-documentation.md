## Why this stub exists

The cross-repo plan lives in `decoy-platform/`. This file records what the CLI repo owes to that plan so a contributor working in this repo can find it without crossing repos.

## What `decoy` owes the plan

### Phase A (foundations)
- Nothing required from this repo in Phase A. The Mintlify scaffold lives in `decoy-web/`.

### Phase B (generated reference) — the big one for this repo

- **B1. `scripts/build_cli_docs.py`** — new script. Walks the Typer app assembled in `src/decoy/__main__.py`, introspects every command (the nine listed in `README.md` plus the standard `--json` / `--quiet` / `--verbose` flags + `decoy run`'s `--master-key` / `--key-label`), and emits one mdx per command. Output lands in `decoy-web/docs/cli/reference/`.
  - Implementation hint: `typer.main.get_command(app)` exposes the underlying Click commands; iterate `command.commands` (or use `click-md` / `typer-cli`'s docs subcommand as a starting point).
  - Pre-commit hook: regen when anything under `src/decoy/cli/` changes; CI fails if the committed output is stale.
  - Source-of-truth rule: the docstring on each Typer command function IS the help text IS the doc. No hand-written second copy.
- **B3 (engine-side support)**: the engine ships JSON Schema export for pipeline YAML; this repo links it from the CLI reference where `decoy validate` / `decoy run` accept a YAML.

### Phase C (tutorials)
Six CLI tutorials, listed in priority order in the master plan. Tutorials live on Mintlify (so in `decoy-web/`), but the **fixtures and example pipelines they reference live in this repo's `examples/` directory.** Each tutorial pins to a specific fixture so it stays runnable. Action items in this repo:
- C1 quickstart pins to `decoy demo` — keep `src/decoy/cli/demo.py` stable (don't rename, don't break output contract). Snapshot test in Phase F3 will lock this.
- C2–C5 each pin to a named example under `examples/`. Audit `examples/` and add any missing pipelines so every tutorial has a known-good source.
- C6 (CI/CD how-to) needs a working GitHub Action example committed under `examples/ci/`.

### Phase F (living loop)
- **F3 snapshot test**: nightly CI runs `decoy demo --json` and `decoy run examples/mask_example.yaml --json`, diffs against a committed golden. Lives in `tests/snapshots/`.
- **F4 PR template**: this repo's `.github/pull_request_template.md` gets the "Docs updated?" checkbox. Today there's no template; create one.
- **F5 `dev-help.md` section**: new section listing the doc surfaces this repo owns — `CLI_UX_GUIDE.md`, `PIPELINE_GRAPH_GUIDE.md`, `docs/architecture.md`, and the autogenerated mdx output in `decoy-web/docs/cli/`.

## Open questions specific to this repo

- Where does `scripts/build_cli_docs.py` write to? Options: (a) commit to `decoy-web/` via a cross-repo bot, (b) PR comment with the diff, (c) artifact uploaded to the Mintlify deploy pipeline. Recommendation: (a) with a `docs/cli-bot` GitHub App + deploy-keys. Reconfirm with the master-plan owner before Phase B1 lands.
- Should `decoy explain <topic>` and the Mintlify content stay in sync, or is it OK for `decoy explain` to be a strict subset (short, terminal-friendly)? Recommendation: subset is fine; both pull from a shared topic dictionary under `src/decoy/cli/explain.py`.
